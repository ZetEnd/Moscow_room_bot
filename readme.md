Moscow Room Bot 🏠

Телеграм-бот для поиска жилья в Москве. Парсит объявления с Циана и показывает ихв формате «Тиндер»: по одной карточке, которую можно листать и сохранять в избранное.

Проект написан для личного пользования — я сам искал комнату в аренду и усталкаждый раз вручную листать сайт. Бот делает это за меня одним нажатием кнопки.

Бот: @moscow_room_finder_bot (ссылку можно заменить на свою)
Как это работает

    Пользователь жмёт «🔍 Искать» (или /start)
    Бот заходит на Циан и забирает свежие объявления (~30 штук)
    Показывает их по одной карточке: фото, цена, адрес, ссылка
    Листаешь кнопками:
        ⬅️ — предыдущая карточка
        ❤️ — сохранить в избранное
        ➡️ — следующая
    Сессия живёт 30 минут. После её окончания все объявления стираются из базы,остаётся только избранное. Новый поиск — новое нажатие «🔍 Искать»

Также можно задать минимальную цену через /minprice (например /minprice 20000),тогда в выдаче будут только объявления дороже этой суммы.

Запуск проекта
1. Клонировать репозиторий и создать виртуальное окружение

git clone https://github.com/ваш-логин/moscow_room_bot.gitcd moscow_room_botpython -m venv .venv.venv\Scripts\activate        # Windows# source .venv/bin/activate   # Linux/Mac

2. Установить зависимости

pip install -r requirements.txt

3. Создать базу данных PostgreSQL

Создать пустую базу (например через pgAdmin или psql):

CREATE DATABASE cian_bot;

4. Заполнить .env

Создать файл .env в корне проекта:

POSTGRES_USER=postgresPOSTGRES_PASSWORD=ваш_парольPOSTGRES_HOST=localhostPOSTGRES_PORT=5432POSTGRES_DB=cian_botBOT_TOKEN=токен_от_BotFatherPOLL_INTERVAL_MINUTES=30REGION=1

Токен бота можно получить у @BotFather (/newbot).
5. Создать таблицы

python Scripts/init_db.py

6. Запустить бота

python -m app.bot

Логика разделена на слои: bot.py не пишет SQL, database.py не знает про Телеграм,final_parser.py не зависит от остальных. Если Циан поменяет вёрстку — правлю один файл.
Про парсер

У Циана нет официального API и есть антибот-защита, поэтому:

    страницы запрашиваются через cloudscraper (притворяемся браузером);
    объявления спрятаны внутри HTML в виде JSON — парсер декодирует их оттуда;
    сайт отдаёт страницу в двух разных форматах (десктопный и мобильный),парсер умеет оба и делает до 3 попыток;
    повторное появление объявления не создаёт дубль в базе — работаетupsert по уникальному cian_id.

Парсинг выполняется только по нажатию кнопки пользователем, фоновогопостоянного опроса сайта нет.
Известные ограничения

    парсится только первая страница выдачи (~30 объявлений за сессию);
    бот рассчитан на одного пользователя;
    сессии хранятся в памяти — при перезапуске бота активная сессия сбрасывается(избранное при этом не теряется, оно в базе);
    объявления не проверяются на актуальность внутри сессии — кого-то уже моглиснять;
    для запуска из региона, где заблокирован Telegram API, нужен VPN/прокси.

Что можно улучшить

    хранить FSM-состояния в Redis, чтобы сессии переживали перезапуск;
    поддержка нескольких пользователей (разделение данных по user_id);
    помечать «протухшие» объявления (нет в свежем парсинге N раз подряд);
    расширенные фильтры (макс. цена, район, комнаты) через inline-меню;
